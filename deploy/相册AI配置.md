# 相册 AI 搜索与自动分类

这项功能来自 [Issue #1](https://github.com/liu7866/couple-home/issues/1) 的建议。AI 是可选项，不配置也可以上传照片、按月份浏览，以及搜索照片备注。已有 AI 结果保存在自己的数据库中，可以继续按描述、标签和分类查找。

## 是否需要自己部署 API

不需要另起一台 AI 服务器。可以使用提供兼容 API 的第三方服务，在小屋后端配置地址、密钥和模型；也可以接自己部署的兼容服务。第三方服务的费用和数据处理条款由部署者自行选择。

当前要求同一个 API 基础地址同时提供：

- `POST /chat/completions`：支持 `image_url` 图片输入，并能返回 JSON 文本，用于生成中文描述、标签和分类。
- `POST /embeddings`：接受文字 `input`，返回浮点数数组，用于对照片描述和搜索文字进行向量匹配；当前支持 1 至 4096 维。

这两个模型通常不同；只有文字聊天能力的服务不足以完成照片分析，只有视觉模型而无 embeddings 接口也无法启用完整功能。本实现不要求 OpenAI 官方账号，但服务需要兼容以上请求格式。协议参考：[图片输入](https://developers.openai.com/api/docs/guides/images-vision)、[Embeddings 接口](https://developers.openai.com/api/reference/resources/embeddings/methods/create)。

## 独立 Node.js 版配置

在服务器自己的 `.env` 中添加下面四项，并换成所选服务的实际值：

```dotenv
ALBUM_AI_BASE_URL=https://YOUR_PROVIDER/v1
ALBUM_AI_API_KEY=your-private-provider-key
ALBUM_AI_VISION_MODEL=your-image-input-model
ALBUM_AI_EMBEDDING_MODEL=your-text-embedding-model
```

基础地址不要带 `/chat/completions` 或 `/embeddings` 后缀，不带查询参数、账号密码或片段；公网地址使用 HTTPS。本机服务可使用 `http://127.0.0.1:端口/v1`、`http://localhost:端口/v1` 或 IPv6 回环地址。

四项齐全且地址格式有效才启用 AI。模型与 API 实际兼容性在首次整理时验证；配置存在不代表服务一定支持图片输入。密钥只保留在后端，不要放进 `public/`、网页脚本、GitHub Pages 配置或公开仓库。

更新源码后执行 `pnpm run build:node`，更新发布包并重启服务。独立版会自动应用新增迁移 `drizzle/0004_album_ai.sql`，只新增 AI 索引与任务表，保留原照片和记录；旧迁移不要修改。正式更新前仍应按[部署说明](node/部署说明.md)备份原数据。

## 原 Sites / Workers 版

在自己的运行环境配置同名变量，`ALBUM_AI_API_KEY` 使用平台的 Secret 保存方式。先应用未执行的数据库迁移，再部署新后端和前端。本功能不改变原平台的身份校验方式，也不补齐迁入个人 Workers 账号所需的独立认证，见 [Cloudflare 限制](cloudflare.md)。

静态 Pages 前端仍需连接部署者自己的后端；API 密钥不随静态导出发布。后端未更新时，新的 AI 接口不可用，普通相册操作保持原有逻辑。

## 使用方法

1. 打开「回忆相册」。输入文字可直接搜索备注、已生成的描述与标签，空格分隔多个词；还能组合月份和分类筛选。
2. 管理员点击「AI 整理照片」。每批最多选取当前筛选结果中 5 张尚未完成的照片，确认提示并勾选同意后才开始发送。
3. 页面展示所选服务地址与数据发送说明。分析发送该批照片的 JPEG 内容和备注，不发送小屋密码、恢复码、其他生活记录或整个相册。
4. 整理时逐张处理。可以选择「完成当前照片后停止」；失败后重试会复用已完成的索引。未整理的照片仍可正常浏览和按备注搜索。
5. 输入自然语言，例如「海边看日落」，点击「AI 找照片」。这会把本次搜索文字发送给向量服务，按与照片描述的相似度查找；分类和月份筛选仍然有效。

分类包括人物、美食、旅行、风景、日常、宠物、节日和其他。标签、描述和分类均由 AI 生成，可能有遗漏或错误；不会覆盖自己填写的备注。分析仅描述可见场景和活动，不要求模型推断人物身份、关系或敏感属性。

## 费用、删除与数据保留

- 每张首次成功整理通常调用一次视觉接口和一次向量接口，已完成且模型配置相同的照片会直接复用结果；每次 AI 搜索调用一次向量接口。失败重试、超时或关闭页面前已发出的调用也可能由服务方计费。
- 普通浏览、文字搜索、月份和分类筛选不调用 AI。每个成员的分析与语义搜索共用每 10 分钟最多 60 次的限制；分析权限仅给管理员，两位成员都能搜索。
- 密钥保存在后端配置，照片描述、标签、分类与向量索引存储在自己的 SQLite / D1 中。服务方仍会收到用户明确确认的内容，应选择自己接受的数据处理方式。
- 管理员可点击「清除 AI 整理结果」移除全部描述、标签、向量及未完成任务，保留照片和原备注。删除单张照片也会删除它的 AI 结果。本地清除不会撤回已经发送给第三方服务的内容。
- Node 服务器数据库快照包含 AI 索引。网页下载的 JSON 完整备份目前保留原照片、备注和生活记录，不包含可重建的 AI 索引；从 JSON 恢复后需要按需重新整理。

## 故障排查与更换模型

| 情况 | 排查方法 |
| --- | --- |
| AI 按钮不可用 | 检查四项配置是否齐全、基础地址格式是否有效，重启后端并确认当前账号已登录；整理入口只对管理员显示 |
| 整理提示服务暂不可用 | 检查密钥额度、图片模型和 embeddings 模型是否支持对应接口；请求会在约 16 秒后超时，原照片会保留 |
| 搜索没有结果 | 先整理照片，再检查月份／分类筛选；只能搜索当前向量模型已索引的照片，相似度结果不保证完整 |
| 提示正在整理 | 另一请求正在处理同一张照片，稍后刷新；中断任务的占用会在 45 秒后过期 |
| 提示过于频繁 | 等待 10 分钟后再用 AI，普通文字搜索仍可使用 |

更换基础地址或向量模型后，旧索引不会与新模型混用；重新点击整理会为当前配置建立索引。若只更换视觉模型并希望重新生成描述，先清除 AI 整理结果，再重新整理。相似度采用归一化向量的点积，当前门槛为 0.2；不同模型的效果应通过自己的测试照片验收。

## 验证范围

新增测试使用虚构照片和本机模拟兼容服务，覆盖分类保存、向量排序、无配置降级、权限和确认、重复分析复用、并发任务、失败清理、删除、限流及前端筛选。代码未绑定或验证任何部署者的真实付费 API；接入具体服务后，需要自行验证模型兼容性、识别质量、时延和费用。
