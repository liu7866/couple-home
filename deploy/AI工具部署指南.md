# 使用 AI 工具协助部署 Couple Home

本指南介绍如何让 Qoder、WorkBuddy、豆包和 Trae 协助部署，包含可以直接复制的任务说明。工具界面和权限随版本变化；本文依据官方说明和本仓库的部署文档整理，**尚未用这些工具在真实云服务器上完成部署验收**。

## 先选择目标

| 目标 | 需要准备 | 结果 |
| --- | --- | --- |
| 本机试用 | 一台电脑、可访问 GitHub 的网络，以及能运行命令的 AI 工具或终端 | 只能在该电脑上通过本机地址访问；电脑停止服务后网站也会停止 |
| 自己的电脑 + Cloudflare Tunnel | 保持运行的电脑、cloudflared；长期使用另需 Cloudflare 账号和域名 | 后端和数据在电脑，外部通过 Tunnel 访问；详见 [Tunnel 指南](cloudflare-tunnel.md) |
| 阿里云或其他 Linux 服务器 | 可连接的服务器、SSH 账号、域名及 HTTPS 证书，并按当地要求完成手续 | 网站和后端运行在自己的服务器上，照片及数据由自己保存 |
| Cloudflare 代理 + Linux 服务器 | 上述服务器和域名，以及自己的 Cloudflare 账号 | Cloudflare 管理域名或代理，后端和数据仍在服务器 |

推荐先用独立 Node.js 版：前后端同一来源，不需要 ChatGPT 登录或 D1/R2。相册 AI 整理默认关闭，普通功能不需要配置 AI 接口或自己部署 AI 模型。服务器版详见 [阿里云 / Linux 部署说明](node/部署说明.md)，Cloudflare 接入详见 [Cloudflare 说明](cloudflare.md)。

**不能只把本项目上传到 Cloudflare Pages 就获得完整网站。** 自己账号下的独立 Cloudflare Workers 版尚缺可信管理员登录和首次初始化适配；不要让 AI 把演示身份、伪造身份头或占位资源当作正式登录方案。

仓库是公开的，一般可匿名克隆，不需要提供 GitHub 密码或 2FA；如果网络无法访问 GitHub，可以先从仓库下载源码并让工具打开解压后的目录。仓库不包含原站的记录或照片，迁移时需另行备份和导入，见 [数据迁移](node/部署说明.md#数据迁移)。

中国内地服务器以域名对外提供网站服务时，需按要求办理备案；以实际服务商和主管部门要求为准，参考 [阿里云备案说明](https://help.aliyun.com/zh/icp-filing/basic-icp-service/support/for-the-record-process-faq)。

## 准备和权限

1. 先决定是**本机试用**还是**服务器部署**。服务器部署需要一台带 systemd 的 Ubuntu / Debian 服务器、可用的 SSH 连接、可访问 GitHub 和依赖的网络，以及能够完成部署的权限。构建需要 Node.js 22.18 或更新版本、pnpm 11.25.0；构建后的 `dist-node/` 运行时只需要 Node.js。
2. 公网部署还需要自己的域名、证书、正确的 DNS 与防火墙配置，并使浏览器访问地址与 `APP_ORIGIN` 一致。服务器或域名可能产生费用；账号登录、实名认证、支付和必要的授权由使用者自己完成。
3. 使用工具的登录或 SSH 认证界面完成授权，不要把服务器密码、SSH 私钥、验证码、GitHub 令牌、API 密钥或初始化码粘贴进 AI 对话、公开仓库或 Issue。检查权限提示，避免把无关目录和数据交给工具。
4. 已有网站先确认目标主机和数据目录，并完成可恢复的备份。不要让 AI 清空或重新初始化现有 `DATA_DIR`、数据库、照片和备份；新测试应使用独立的空目录与虚构数据。

工具可能只能读取信息，不能执行命令；即使能执行，本地工作区也不等于服务器工作区。先在工具中确认**命令实际运行在哪台机器、哪个目录**。

### 连接 SSH 的准备

若使用 Qoder 或 Trae 的 SSH 工作区，可先在自己电脑的 `~/.ssh/config` 中配置主机；Windows 通常是当前用户目录下的 `.ssh/config`。以下只是模板，必须换成自己的服务器地址和 SSH 用户名：

```sshconfig
Host couple-home-server
    HostName YOUR_SERVER_IP
    User YOUR_SSH_USER
```

非默认端口可增加 `Port`；使用 SSH 密钥时按自己的云服务商说明配置本机密钥或 `IdentityFile` 路径，**不要粘贴私钥内容**。使用者可以在本机终端运行 `ssh couple-home-server` 检查连接，并在认证界面自行完成登录；首次连接应核对服务器指纹。配置完成后，在 AI 工具的 SSH 主机列表中选择 `couple-home-server`。如果连接失败，先检查服务器是否运行、SSH 端口和账号是否可用，再按工具的官方说明排查。

## 通用任务：先在本机试用

打开一个独立的空工作目录，在支持文件和终端操作的 AI 工具中发送：

```text
请帮我在这台电脑本地试用 Couple Home：
https://github.com/liu7866/couple-home

请先检查当前目录和环境，阅读 README 及 deploy/node/部署说明.md。
在独立目录克隆仓库，按文档检查或准备 Node.js 和 pnpm，安装依赖，
构建独立 Node 版并运行相关测试。用单独的空数据目录启动本机预览，
只监听回环地址；如果端口占用，选择空闲端口并同步设置 APP_ORIGIN。
告诉我实际访问地址、启动方式、测试结果和未完成的步骤。
不要读取、覆盖或删除已有小屋数据，不要创建真实账号或索取密码。
```

打开工具报告的本机地址后，由使用者自己设置两位成员的密码。该地址只用于本机，不能因为本机能打开就认定公网部署成功；停止进程或关闭电脑后，预览也会停止。

## 通用任务：部署到服务器

先在工具中连接目标服务器，确认机器、账号和工作目录，再发送：

```text
请协助部署 https://github.com/liu7866/couple-home 的独立 Node.js 版。
目标是我已连接并授权的 Linux 服务器；请先确认实际主机、工作目录、
已有服务和数据，再阅读 README、deploy/README.md 和
deploy/node/部署说明.md。如果发现已有小屋或数据，请先说明备份与更新方案，
不要初始化、覆盖或删除现有数据。

请按文档构建并测试，配置独立的持久化数据和备份目录、systemd 服务、
定时备份、Nginx 和与我的域名一致的 HTTPS。应用仅监听本机，
不要把数据库或照片目录设成公开静态目录。Cloudflare 是可选项，
只有在我要求并完成授权后才按 deploy/cloudflare.md 配置。

请先用独立目录和虚构数据验证；正式小屋由我自己在网页设置密码。
不要在对话或报告中输出密码、私钥、验证码、初始化码和其他密钥，
也不要索取这些信息。需要账号登录、授权或我手动操作时说明具体步骤。
最后分别列出实际执行的操作、测试结果、访问地址和未验证的事项；
不要把构建成功或本机预览写成公网部署成功。
```

全新公网小屋首次设置需要初始化码。按照 [服务器部署说明](node/部署说明.md#阿里云-linux-部署)由部署者私下查看后，在网站首次设置页面填写；不要把包含初始化码的日志贴给 AI。已经初始化的小屋不应再次创建。

## 通用任务：给已有服务器接入 Cloudflare

先确认独立 Node 版已在服务器启动，并准备好可用域名、源站 HTTPS 证书和自己的 Cloudflare 账号。如果 AI 工具没有 Cloudflare 控制台访问能力，可以让它给出步骤，由使用者自己在控制台操作。

```text
请根据 https://github.com/liu7866/couple-home 中的
deploy/cloudflare.md，协助我把已有的独立 Node 服务器接入 Cloudflare。
先确认目标服务器、域名、DNS 和源站 HTTPS 证书，保留现有数据和服务。
在我完成必要的 Cloudflare 登录或授权后，协助设置域名解析；
如需开启代理，使用 Full (strict)，不要缓存登录、API 或私人照片。
请检查 APP_ORIGIN 与实际 HTTPS 地址一致，并分别验证源站与最终域名。
如果没有控制台权限，请明确告诉我需要手动完成的操作。
不要索取或在对话中输出密码、令牌、验证码、私钥和初始化码。
最后列出已执行步骤、实际测试结果和仍需处理的事项。
```

Cloudflare 接入不会替代后端或自动迁移数据；没有真实配置和验证时，不应声称已经上线。

如果希望后端运行在自己的 Windows 电脑而不是云服务器，请让 AI 先阅读 [电脑 + Cloudflare Tunnel 部署指南](cloudflare-tunnel.md)，选择临时体验或固定域名路线；已有数据必须先备份，测试应使用独立目录，不要将 Tunnel 令牌、初始化码或密码粘贴到对话里。

## Qoder

1. 安装并登录 Qoder。新建任务，选择**编程**工作区和有明确权限的文件夹；本机试用时使用本机工作区。使用上面的本机任务，让工具在该目录获取仓库、构建和启动。
2. 部署服务器时，先在 Qoder 选择“连接 SSH”或“设置 → 连接”，添加或选择已配置的 SSH 主机，完成认证后选择服务器上可读写的项目工作目录。如果没有可选主机，先按官方说明配置本机 SSH，或请熟悉服务器的人员协助。确认窗口显示的是目标远程工作区，再发送上面的服务器任务。
3. 按界面提示检查并授权需要的命令。若 Qoder 只能在本机运行，不能据此认定服务器已经修改；连接失败时先处理 SSH、网络和权限。

参考：[Qoder CN 执行环境及 SSH 工作区](https://docs.qoder.cn/qoder/execution-environments)、[Qoder 安全与授权](https://docs.qoder.cn/qoder/security-and-authorization)。不同版本入口可能有差异。

## WorkBuddy

1. 打开 WorkBuddy，新建任务并选择独立工作空间。发送上面的本机任务，允许所需的文件和命令操作；可先保留默认权限，逐项检查提示。
2. 服务器部署时，先确认当前版本能调用终端或 SSH 客户端，并且有可用的服务器连接与执行权限；再告诉它部署目标，发送上面的服务器任务。必要时由使用者在 SSH 或云控制台登录界面完成认证。
3. 如果当前环境没有终端、网络或远程连接能力，让它按文档给出逐步命令，再由使用者在服务器终端执行；不要把生成的步骤当作已经执行。

参考：[WorkBuddy 默认权限与安全沙箱](https://cloud.tencent.com/document/product/1831/134401)。具体能力取决于版本、工作空间和授权。

## 豆包聊天版

1. 把仓库地址和部署目标发给豆包，请它先阅读本仓库的 README 与服务器部署说明。如果当前版本无法读取链接，使用者可以复制**公开文档内容**给它；不要复制私人配置或日志。
2. 如果当前豆包会话没有终端和服务器访问能力，请它提供适合服务器系统的分步命令，并说明每步如何检查。使用者在自己已经认证的 SSH 终端逐步执行；不要把密码、验证码、私钥或含密钥的输出粘贴回对话。
3. 请它根据实际执行结果协助排错。只有用户确实执行并验证后，才能判断部署是否成功。若当前版本提供经过授权的终端或远程操作，也可以使用上面的通用任务，但仍须确认执行位置和结果。

## Trae

1. 打开 Trae 并登录；本机试用时打开独立目录，在可执行命令的 Agent / Builder 会话中发送上面的本机任务。
2. 部署服务器时，通过 Trae 的 Remote SSH 连接目标主机，完成认证并打开远程工作目录，然后在支持执行命令的会话中发送上面的服务器任务。确认任务运行在远程主机，不是本地预览。
3. 根据界面提示检查命令、授权和运行结果。Remote SSH 的入口与模型可用性随版本变化；若连接失败，先确认服务器 SSH 和网络。

参考：[Trae Remote SSH 说明](https://developer.volcengine.com/articles/7481503983064842252)。

## 验收清单

- 本机试用：给出实际访问地址，首页能打开；两位成员的密码由使用者自己设置并登录。测试不要复用真实数据目录。
- 正式部署：通过自己的 HTTPS 域名打开首页并检查 `/healthz`，由使用者验证两位成员登录、虚构照片上传和下载备份；重启服务后确认数据仍在。
- 检查定时备份是否执行、快照是否可校验，并将备份另存到服务器以外的私有位置。服务器快照含密码哈希和会话等敏感信息，不公开分享。
- 记录部署的仓库提交、服务器版本、实际测试及尚未测试的项目。服务构建成功、AI 回复“完成”或 GitHub 有更新，都不代表公网、HTTPS、登录和数据持久化已经通过验收。

相册 AI 需要另行配置兼容服务与后端密钥，且调用可能产生费用；见 [相册 AI 配置](相册AI配置.md)。本指南不改变或自动部署任何现有网站。
